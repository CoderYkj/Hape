## 1. 三条并行主线

三件事互相**不阻塞**，可以并行推进（一条线的外部条件卡住时，另两条照走）。

### 主线 A：观测 → 容量

| 顺序 | 项 | 依赖 | 状态 |
|---|---|---|---|
| A1 | Prometheus 接上（抓 `/metrics`） | 一台能跑 Prometheus 的机器 | 🟡 规则文件在，未接线 |
| A2 | 补齐剩下 4 条告警（5xx>1%、分配卡住、僵尸对局、经济 internal） | A1 | ⬜ 只在 `rules/95` 文档里 |
| A3 | 压测（每场对局的 QPS/延迟/并发会话） | A1 | ⬜ |
| A4 | SLO 与容量决策（要几台、什么规格） | A2 + A3 | ⬜ |

### 主线 B：引擎内（两个二进制）

| 顺序 | 项 | 依赖 | 状态 |
|---|---|---|---|
| B1 | 参考 DS（`ds/`，Go） | 无 | ✅ 容器内真打一局 |
| B2 | UE5 Dedicated Server（替换 B1 的二进制） | UE5 引擎 + 许可 | ⬜ 契约已定（spec 0012） |
| B3 | UE5 客户端（登录/排队/连 DS/结算页） | B2（要先有真机可连）+ 协议（已定） | ⬜ C++ 片段未编译 |
| B4 | 真机联调（一次完整对局，人真的在里面打） | B2 + B3 | ⬜ |

### 主线 C：平台演进

| 顺序 | 项 | 依赖 | 状态 |
|---|---|---|---|
| C1 | mTLS 或短期凭证（替代长期共享密钥） | 无 | ⬜ |
| C2 | M4 服务拆分：rank/matchmaking 独立进程 | C1 + 消息队列或 gRPC | ⬜ |
| C3 | 进程内 sink 换消息总线（结算扇出跨进程） | C2 | ⬜ |
| C4 | 多实例 reconciler 单活选主 | C2（单进程时无意义） | ⬜ |

## 2. 现在就能做、不被任何外部条件阻塞

| 项 | 为什么现在做 | 完成判据 | 状态 |
|---|---|---|---|
| Edgegap `env_vars` 复验 | 机制在本地/CI 容器验过；厂商侧注入未验，而镜像已经发布（`:<sha>-ds`） | container logs 出现 `runtime_token=present(len=N)` | ⬜ |
| 计费对账 | 回收已实测，但"不再计费"没验过——钱的最后一段 | 释放时刻与停计费时刻对齐；`/v1/deployments` 归零 | ⬜ 需账单访问 |

## 4. 明确未实现的技术项

| 类别 | 项 | 说明 |
|---|---|---|
| 引擎 | UE5 Dedicated Server | 环境契约、双凭证、`result_id` 幂等都已定；二进制未建 |
| 引擎 | UE5 客户端 | `docs/ue5-client-model.md` 的 C++ 是形状指引，未在引擎里编译 |
| 厂商 | GameLift / Agones 适配器 | 照 `pkg/battlealloc/edgegap.go` 的结构写，契约测试用假服务 |
| 对局 | DS 掉线重连 | 需要 DS 侧保存每局连接状态 |
| 对局 | 战报 `schema_version` | 加字段，便于以后兼容旧战报 |
| 对局 | 反作弊（异常战报检测） | 现在是"谁能提交 + 提交什么"的边界，不是行为分析 |
| 平台 | 多实例 reconciler 单活选主 | 现在多实例会重复 Release（安全但费配额） |
| 运维 | 生产数据库运维 | 备份/复制/连接池/密码策略；脚本有，真机没跑过 |
| 运维 | 生产部署本身 | systemd、TLS 反代、磁盘水位、跨机恢复 |
| 安全 | mTLS / 短期凭证 | scope 解决"能做什么"，不解决"凭证长期有效" |
| 安全 | 凭证越权告警 | 现在只有日志与计数，没有"某凭证被拒 N 次"的告警 |
| 工程 | UE5 侧 CI（引擎构建） | 需要引擎与许可，且构建很重 |

## 5. 已关闭（对照，成本与节奏的参考）

| 项 | 规格 |
|---|---|
| 登录收口 + 后端签发玩家 token | ADR 0010 |
| 自有 DS 镜像 + 每场凭证容器内验证 | spec 0012 |
| 客户端对局闭环（by-match → UDP → 结算） | spec 0013 |
| Edgegap 分配 + 回收回读（含真实时序实测） | spec 0015 |
| 凭证轮换（多凭证并行 + `caller=` 日志） | spec 0014 |
| 凭证最小权限（scope，默认拒绝 + 覆盖性测试 + 观察期） | spec 0016 |
| 回收指标 + 1 条告警规则 | spec 0015 |

## 6. 怎么更新这页

1. 状态变化先改这里（Markdown）；同时改对应 spec 的「状态」行与 `docs/architecture-map.md` 的表格。
2. 然后同步 `docs/roadmap.html`（结构与本节一致）。
3. 关闭一项时：从"未实现/现在该做"移到 §5，并写清规格编号——没写规格的"完成"不算完成。
